# 代码审查与上线前验收清单

## 阶段 A：静态审查

- [ ] 源码、测试、依赖锁定、README、Docker Compose、迁移文件完整。
- [ ] 没有明文默认密码、真实用户信息或内网配置被写入源码/公开仓库。
- [ ] 权限在视图/服务层真正执行；不能只靠 UI 隐藏操作按钮。
- [ ] 数据库表模型具有合理的唯一/外键/检查约束；申请状态变化用事务。
- [ ] 所有导入/解析行写 source provenance，不会删除不匹配行。
- [ ] file SHA256 与业务版本、source path 分开存储；重复内容防止重复申请。
- [ ] 业务字段按表头和模板识别，不依赖单一固定列号。
- [ ] 原始数量保存；Decimal 保存数字，单位独立；无空值强转零。
- [ ] 文件上传校验类型、大小、路径穿越；无任意读写/解压执行漏洞。
- [ ] Excel 导出不会形成公式注入，且保留用户文字、中文和特殊字符。
- [ ] 所有已审核单据修改留版本和审计，前后变更可查。

## 阶段 B：运行审查

- [ ] 启动新环境，跑迁移、创建管理员、初始化源数据。
- [ ] 原始 15 sheets 和 14 个归档 xlsx 可枚举，导入成功/待确认/不支持三类之和可解释。
- [ ] 随机抽取跨月份同物料数据，逐项核对源文件/行/数量，尤其 `200m` 和错列 ASM。
- [ ] 测试相同内容归档的两个目录，防止汇总重复。
- [ ] 执行自动测试；导出 xlsx 后重新解析核对两类 sheet、21列及所有字段。
- [ ] 至少两个不同账号从浏览器操作，权限、提交/审批/退回和并发测试通过。
- [ ] 执行数据库和上传文件备份、恢复演练。

## 阶段 C：业务验收（仍需用户确认）

- [ ] “科长”列是审批人名字还是仅业务字段？目前按原字段保存，不强制绑定用户角色。
- [ ] “NVB2”、“未交”、“需要请购”具体怎么算？V1 暂时都不自动计算。
- [ ] 7 组重复新料号是否为共享件/不同规格，管理员人工选择合并策略。
- [ ] 18列表双“未交/库存”究竟代表什么？人工确认，必要时支持第二快照。
- [ ] 费用表、治工具表是否在第二阶段纳入独立申请流程。

## 审查输出格式

- `结论`：PASS / PASS WITH ISSUES / FAIL。
- `缺陷清单`：严重性 P0/P1/P2、复现方法、影响数据、建议修复。
- `风险`：历史数据准确性、版本冲突、账号安全、备份、生产网络。
- `证据`：具体测试输出、代码位置、测试命令及截图（有则提供）。

> 本清单属于预设验收要求；只有 Codex 交回真实代码和执行日志以后，才能填写实际审查结论，不能预先宣称通过。
